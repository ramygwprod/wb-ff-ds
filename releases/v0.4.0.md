# v0.4.0

**Date:** 2026-11-14, 02:43 EET (UTC+02:00)
**Goal achieved:** the pipeline spine. The guarantees now sit in the structure, not only in instructions and a CI run at the end. The design knowledge is checked data with generated documents, every open question lives in one decision register that the checks enforce, rules are enforced by checks proven on samples, and the host enforces what each agent may write. The layout foundation is the first content and the test case.

## Added

### Knowledge registry (spine S1–S2)

- **Schemas** in `tools/registry/schemas/`: `common`, `sources`, `rules`, `decisions`, `agent`, `checks` and `run-log` (JSON Schema 2020-12). Every allowed value is explained in its schema, and the generator refuses a description that doesn't cover its values.
- **Validator** `tools/registry/validate.mjs`: a schema stage, then a cross-reference stage. Each issue has a code, a severity, the file and a JSON Pointer path, and a broken file never sets off a cascade of follow-on errors.
- **The layout foundation as data:** `knowledge-base/foundations/layout/sources.json` (62 sources) and `rules.json` (63 rules in 9 groups). It was converted from the hand-written drafts with a before/after proof that found 0 unexpected differences.
- **Decision register** `knowledge-base/decisions.json`: 43 decisions, 39 answered and 4 open (DEC-022, DEC-023, DEC-029, DEC-042).
- **Generator** `tools/registry/generate.mjs`: writes `decisions.md`, `sources.md` and `rules.md` from the JSON. `--check` fails when a generated file differs from what its JSON produces. The `.md` files in `knowledge-base/` are now generated: change the JSON, then run `npm run registry:generate`.

### Register enforcement and agent manifests (S3)

- **Enforced:**
  - An approved rule can't wait on an open decision.
  - A "proposed" rule must wait on one.
  - Only an open decision may list what it blocks.
  - A gap only points to its decision, and a gap whose decision is answered must be closed.
  - Open decisions can expire.
  - A rules file is approved only when every rule in it is.
- **Agent manifests** (`agent.json` next to its foundation; reviewers in `knowledge-base/agents/`):
  - **Tools:** a closed allowlist with no Bash.
  - **Write scope:** may never reach protected paths (the decision register, any manifest, `tools/`, configuration, the run log, dot folders).
  - **Finish gate:** checks that must be real npm scripts, plus a retry limit.
  - **Reviewers:** each one named must exist.
  - **Claude Code agent files:** generated locally from each manifest and not published (DEC-039).

### Tested checks (S4)

- **Check registry** `tools/checks/registry.json`: nine checks enforcing ten layout rules (L-T7, L-F1, L-L1, L-L3, L-L6, L-L8, L-O1, L-R4, L-E1, L-E2). Each check is an error, never a warning, and each rule records its kind of check (`data`, `source` or `rendered`).
- **CSS lint:** `@eslint/css` rules plus seven local rules (`tools/checks/css/`). Every message starts with the rule ID it enforces.
- **Proof:** 18 sample files the checks must pass or fail, matched line by line. Further tests confirm every check ran, every `ng lint` config applies each check to the right files, and the Baseline data inside `@eslint/css` agrees with the layout sources.

### Hooks (S5)

- **Write guard** (`PreToolUse`):
  - A sub-agent without a manifest may not write.
  - Every other sub-agent writes only inside its manifest's scope, never a protected path, never outside the repository, and not through a symlink.
  - It fails closed.
  - The main session is left to Claude Code's normal permissions.
- **Finish gate** (`SubagentStop`): regenerates the Markdown, runs the manifest's checks, and reads the agent's `Outcome:` line. When the checks fail it sends the agent back, up to its retry limit.
- **Public run log** `knowledge-base/runs/YYYY-MM.jsonl`:
  - Structured fields only, with no free text.
  - An agent without a manifest is logged as `unregistered`.
  - A path is logged only when git publishes it.
  - The writer refuses any entry that doesn't match the schema, and `registry:check` scans the log.
- **Installer** `tools/hooks/install.mjs`: a person runs it, because agents can't edit settings files.

### CI (S6)

- New steps: **Registry check** (`npm run registry:check`) and **Tools tests** (`npm run test:tools`). The job name is unchanged, so the required checks still match.
